KAS key IDs now support up to 128 bytes. The migration changes `asym_key.key_id`
and its inherited column in `key_access_server_keys` to `TEXT`, with an inherited
check constraint on `octet_length(key_id)`. Multibyte characters count toward the
byte limit. Existing keys and uniqueness constraints are preserved. The three
active public key views are recreated with their existing definitions because
PostgreSQL requires this when changing the column type.

Rollback restores the 36-character column limit and fails without truncating data
if longer IDs still exist. Remove or replace those keys before rolling back.
