# [OpenTDF] Keep embedded assertion keys from overriding configured verification keys

## Summary
What needs attentionAssertion.Verify appends header JWK/x5c public keys to the caller-supplied key. The reader passes its configured assertion verifier to that function. The existing test explicitly expects acceptance with an unrelated supplied key. This permits self-signed assertions to satisfy a configured trust decision.
Preconditions and impact limitsApplication configures an assertion verification key and accepts attacker-authored assertions.
Payload and assertion aggregate consistency checks still apply.
Reviewed severity: high. Jira priority: Major. This assessment is based on static source inspection; no new runtime reproduction was performed. Production exposure and premium DSP dependency applicability remain unverified.
Proposed remediationMake configured-verifier mode enforce the configured trust anchor. Keep any supported self-signed mode explicit and separate; cover embedded JWK and x5c paths.
Acceptance criteriaAdd focused regression coverage for the source/control/sink behavior described above.
Verify malformed or adversarial input is rejected before the unsafe operation.
Verify valid input still works and record the actual checks run.
