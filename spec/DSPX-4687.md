# [OpenTDF] Reject ZIP64 lengths that cannot be represented before manifest allocation

## Summary
What needs attentionZIP64 lengths narrow to signed values. ReadAllFileData checks only length > maxSize and then readBytes allocates that length. A wrapped negative length reaches make before KAS authentication.
Preconditions and impact limitsConsumer calls SDK.LoadTDF on an attacker-controlled archive.
Reviewed severity: medium. Jira priority: Medium. This assessment is based on static source inspection; no new runtime reproduction was performed. Production exposure and premium DSP dependency applicability remain unverified.
Proposed remediationCheck integer representability, nonnegative lengths, checked offsets, and physical archive bounds before allocating or seeking.
Acceptance criteriaAdd focused regression coverage for the source/control/sink behavior described above.
Verify malformed or adversarial input is rejected before the unsafe operation.
Verify valid input still works and record the actual checks run.
